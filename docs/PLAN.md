Пользователь принимает 5 решений в рамках бюджета 100 → Astana Quality of Life Score + AI-объяснение.

## Архитектура
data/*.json → src/lib/simulation/data.ts (Zod-проверка и адаптер, без копий каталога)
  → simulate.ts / validate.ts → index.ts (единый TS-контракт)
  → React UI и серверные Next.js Route Handlers → AI/fallback.
Числа считает только движок. LLM объясняет JSON и вызывает инструменты, сам не считает.
Тяжёлый поиск и его мемоизация — только на сервере, без клиентского bundle.
Baseline: simulateScenario({decisions: []}); пользовательский валидатор требует ровно 5 мер.
data/geo/ сохранён для react-leaflet; runtime не обращается к Overpass.

## Контракты оставшихся фич
- E3: полный перебор валидных наборов и размещений; серверная мемоизация по данным/ограничениям; suggestSwaps не предлагает невалидные замены. Цель холодного поиска <5 сек, без подмены результата fixture.
- E4: findBest(constraints: {budgetMax, mustInclude, exclude, mustIncludePlaced, avoidDistricts, minDistrictScore}). mustIncludePlaced фиксирует меру и район. pareto(step) возвращает оптимальный Score при бюджетах с заданным шагом.
- E4: timeline(scenario) содержит q=0…8. Доля эффекта max(0,q−L)/8; синергия действует при q > max(L1,L2); timeline[8] == evaluate (текущий evaluate — simulateScenario). Внутренние значения не округлять.
- E5: react-leaflet + OSM, ΔD с нейтральным серым нулём / D после / количество критичных; hover до→после, дельта, топ-3 показателя и меры; маркеры мер в центроидах со смещением; городские меры отдельной плашкой; слабейший район выделен, «тянет 30% Score»; районы без локальных мер помечены; список «Что ухудшилось»; схема Алматы явно обозначена.
- A3: OpenAI-совместимый SDK, LLM_BASE_URL / LLM_API_KEY / LLM_MODEL; инструменты — функции TS-движка, не повторение формул; не более 6 итераций; режимы explain/chat, ответ {answer, trace}. Trace показывает вызовы и результаты инструментов, не приватные рассуждения модели. Без ключа сохраняется текущий fallback. Текущий OPENAI_API_KEY поддерживается до миграции A3.
