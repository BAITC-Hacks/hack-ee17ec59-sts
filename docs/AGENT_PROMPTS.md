# Задания для coding agents

## Как использовать

Каждый участник начинает с отдельной ветки и дает своему coding agent соответствующее задание ниже. Перед выполнением любой задачи agent обязан прочитать `AGENTS.md`, `docs/PRD.md`, `docs/SIMULATION_SPEC.md` и `docs/ARCHITECTURE.md`.

Agent не должен самостоятельно менять продуктовые правила, формулу или контракт между частями. Если нужного типа еще нет, он создает локальный минимальный mock и явно помечает место подключения вместо изменения чужих файлов.

## Prompt 1 Damir Движок и основа

```text
Ты работаешь над HackAlem MVP «Аким на 5 часов».

Сначала полностью прочитай AGENTS.md, docs/PRD.md, docs/SIMULATION_SPEC.md и docs/ARCHITECTURE.md. Эти документы являются источниками истины.

Твоя зона ответственности:
1. Создать минимальный Next.js App Router проект с TypeScript и Tailwind в текущем репозитории.
2. Создать общие доменные типы и модуль src/lib/simulation.
3. Точно перенести все районы, показатели, веса, инициативы, лаги, синергии и конфликты из SIMULATION_SPEC.md.
4. Реализовать чистые функции validateScenario и simulateScenario без React, сети и OpenAI.
5. Возвращать полный SimulationResult по контракту ARCHITECTURE.md.
6. Добавить эталонные сценарии как reusable fixtures.
7. Проверить baseline 52.56 и эталонный сценарий примерно 56.5.
8. Создать .env.example и убедиться, что .env.local игнорируется.

После первичного scaffold не реализуй Scenario Builder, Results UI или AI route. Не меняй числовые правила. Не добавляй базу данных, auth или GPU зависимости.

В конце перечисли созданные файлы, фактические контрольные значения и инструкции для подключения UI.
```

## Prompt 3 Shah Результаты и AI

```text
Ты работаешь над HackAlem MVP «Аким на 5 часов».

Сначала полностью прочитай AGENTS.md, docs/PRD.md, docs/SIMULATION_SPEC.md и docs/ARCHITECTURE.md. Эти документы являются источниками истины.

- src/app/api/analyze/**
- src/schemas/**
- fallback explanation
- README.md и docs/DEMO.md по мере изменения реализации

Сделай следующее:
1. Реализуй Results Dashboard, который принимает готовый SimulationResult и ничего не пересчитывает.
2. Покажи итоговый Score, delta, бюджет, before/after районов, критические показатели, синергии и вклад мер.
3. Реализуй POST /api/analyze с Zod validation.
4. Передавай OpenAI только рассчитанный JSON. Запрети модели менять числа, пересчитывать Score или придумывать эффекты.
5. Требуй структурированный AnalysisResponse из ARCHITECTURE.md.
6. При отсутствии ключа, ошибке, timeout или неверном ответе возвращай качественное детерминированное объяснение с source fallback.
7. AI загрузка не должна задерживать показ Score.
8. Обновляй README только фактическими командами и технологиями.

Не редактируй simulation engine, Scenario Builder или общую page integration. Не добавляй базу данных, auth, GPU или тяжелую AI orchestration библиотеку.

В конце перечисли props Results Dashboard, формат API и необходимые environment variables.
```

Не рефактори соседний код, не меняй публичные контракты, зависимости, дизайн или продуктовые правила. После исправления сообщи точные измененные файлы, причину ошибки и минимальную проверку результата.
