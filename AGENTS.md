# AGENTS

## Цель проекта

За ограниченное время создать работающий и воспроизводимый MVP задачи «Аким на 5 часов». Приоритеты в таком порядке:

1. Корректная симуляция и валидация.
2. Полный пользовательский сценарий от выбора мер до результата.
3. Понятное объяснение результата с помощью AI.
4. README и воспроизводимость.
5. Визуальная полировка и дополнительные функции.

## Источники истины

- `docs/PRD.md` определяет продукт и критерии приемки.
- `docs/SIMULATION_SPEC.md` определяет данные, правила и формулу. При расхождении с кодом исправляется код.
- `docs/ARCHITECTURE.md` определяет границы модулей и контракты.
- `docs/DELIVERY_PLAN.md` определяет текущие владельцы работ и сроки.

Не изменяйте правила симуляции ради более красивого результата. Не позволяйте LLM считать или исправлять числовой Score.

## Технические решения

- Next.js App Router и TypeScript.
- Один репозиторий и одно приложение.
- Детерминированный движок в `src/lib/simulation` без React, сети и OpenAI.
- UI вызывает движок локально для мгновенного результата.
- OpenAI вызывается только через серверный route handler.
- Валидация внешних данных выполняется Zod схемами.
- Секреты хранятся только в `.env.local`; в Git попадает только `.env.example`.
- База данных, авторизация и GPU в MVP не используются.

## Правила реализации

- Сначала реализуйте основной сценарий, затем крайние случаи и оформление.
- Каждая новая функция должна поддерживать сценарий из PRD. Не добавляйте функции «на будущее».
- Любые числовые значения районов, мер, весов и формул хранятся централизованно, без копий в компонентах.
- Денежные ограничения и правила выбора проверяются одной общей функцией `validateScenario`.
- `simulateScenario` принимает только валидный сценарий либо возвращает типизированную ошибку.
- AI получает рассчитанный JSON и явно запрещается менять числа или придумывать факты.
- При недоступности AI интерфейс показывает детерминированное резервное объяснение.
- Ошибка AI не должна ломать расчет или экран результата.
- Не добавляйте зависимость, если задача решается небольшим количеством понятного кода.
- Не переименовывайте и не перемещайте чужие модули во время параллельной работы без согласования.

## Параллельная работа

Распределение основано на независимых вертикальных частях, а не на уровне участников.

- Damir: `src/lib/simulation/**`, базовые типы и финальная интеграция.
- Rasul: `src/components/scenario/**` и пользовательский ввод.
- Shah: `src/components/results/**`, `src/app/api/analyze/**` и AI анализ.

Общие файлы `package.json`, `src/app/page.tsx`, `src/app/layout.tsx`, глобальные стили и общие типы редактируются последовательно. Перед изменением общего файла владелец пишет команде, после изменения сразу делает маленький commit.

Рекомендуемые ветки:

- `feature/simulation-engine`
- `feature/scenario-builder`
- `feature/results-ai`

Damir объединяет ветки в `main` на двух контрольных точках из `docs/DELIVERY_PLAN.md`. Коммиты должны быть небольшими и описывать один законченный шаг. Не коммитьте сломанный build в `main`.

## Контракт между частями

UI формирует `ScenarioInput` из пяти решений. Симулятор возвращает `SimulationResult`. Results UI отображает этот объект без повторного расчета. AI route принимает только `SimulationResult` и возвращает `AnalysisResponse`.

Контракты из `docs/ARCHITECTURE.md` согласуются до параллельной реализации. Если контракт нужно изменить, сначала меняется документ и сообщается всем участникам.

## Definition of done

Задача считается готовой, когда:

- пользователь может выбрать ровно пять мер;
- бюджет и все ограничения проверяются до расчета;
- baseline равен 52.56 с допустимой погрешностью округления;
- эталонный сценарий дает примерно 56.5;
- результаты меняются при изменении решений;
- показаны бюджет, итоговый Score, delta, районы и критические показатели;
- AI объяснение основано только на рассчитанных данных;
- приложение переживает ошибку AI;
- секреты отсутствуют в Git;
- README содержит точные команды установки и запуска;
- проект запускается с чистого клона.

## Запрещенный scope до feature freeze

- Аутентификация и профили пользователей.

- Реальная карта города.
- Многопользовательский режим.

- Использование NVIDIA Brev без функции, которой действительно нужен GPU.
